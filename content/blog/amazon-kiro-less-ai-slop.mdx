Amazon Kiro is trying to make vibe coding less chaotic (so less AI slop).

The AI coding space has been exploding with “vibe coding” tools where you throw prompts at AI and hope for the best. It’s fast, but let’s be honest — it’s chaotic.

Amazon just launched Kiro (currently in preview, free and uses Claude models), and it’s taking a different approach.

I’m particularly interested in these two capabilities which will be copied by others soon enough because they’re much needed.

## Specs

Instead of jumping straight into code, Kiro follows a structured process. It creates a `requirements.md` file first, then a `design.md` file, and only then starts coding. You can go back and make changes to these files or refer to them in your prompts to steer the agent in the right direction.

No more spending hours cleaning up AI slop code. You get properly planned, documented code from the start.

## Hooks

The hooks system lets you customize how the AI behaves at different stages. Want it to follow your team’s coding standards? Create a hook for that. Need specific testing patterns? Hook. Security requirements? Hook.

You can create hooks that are event triggers — “If something happens then do this” rules for agents so they’ll automatically perform actions.

Easy example: change API spec and the agent will automatically update documentation or run unit tests.

This space is heating up fast. Cursor is still dominating, Claude Code is silently expanding, Gemini CLI recent release, Windsurf’s team joining Google after their OpenAI deal fell through. Now we have Kiro entering the ring.

The competition is pushing everyone toward more structured, context-aware development tools. Less AI slop and more well-documented, maintainable code.
