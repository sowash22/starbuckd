Before you hear it from others, hear it from me.

It’s the new buzzword in AI circles. Everyone from Karpathy to Tobi Lütke is talking about it.

I get it. And I mostly agree.

Because if you’ve built anything serious with LLMs, you know the real challenge isn’t just what you ask the model. It’s what the model sees when it answers — and that’s where things get messy.

It sees a blend of retrieved documents, embeddings, system messages, API responses and memory… most of it is indeterministic and constantly changing.

But let’s not pretend this is a clean break. What we’re calling “context engineering” today often feels a lot like what “prompt engineering” was yesterday.

Context is part of the prompt — or maybe the prompt is part of context. Either way, calling it “context” makes sense. Most people think of “prompt” as just the message they type, when there’s a lot more going on.

Anyway we’ve improved the process with agentic RAG, ReAct agents, tools like MCP, A2A, context evals and more retrieval-aware flows. These are real advances.

But at its core, it’s still a lot of iterating, nudging, and injecting things into the prompt or context (whatever you call it) until something sticks.

The bottom line?

Terms come and go.

Tinkering stays — and always evolves.

Because we’re fundamentally dealing with indeterministic systems.
